# Immich

Photo and video management. See the [Immich documentation](https://docs.immich.app/).

## Requirements

- **CPU:** the machine-learning container requires x86-64-v2 (SSE4.2, POPCNT) on amd64. Check with
  `grep -o -w -E 'sse4_2|popcnt' /proc/cpuinfo | sort -u`.
- **Memory:** Immich requires at least 2 GB for Postgres when memory limits are used. Machine learning
  (face recognition, smart search) may use up to 4 GB during the initial scan.
- **Mobile apps** must have the same major version as the server.

## Storage

| Path in `.env`         | Container path               | Content                                      |
| ---------------------- | ---------------------------- | -------------------------------------------- |
| `IMMICH_UPLOAD_PATH`   | `/data`                      | Uploads, thumbnails, encoded videos, backups |
| `IMMICH_EXTERNAL_PATH` | `/usr/src/app/external` (ro) | Existing photo library, read-only            |
| `./model-cache`        | `/cache`                     | Downloaded machine-learning models           |

Immich writes automatic database backups to `<upload>/backups`. They are not a replacement for a backup of the
upload directory itself.

### Dedicated Upload Folder

When Immich becomes the primary photo library, put `IMMICH_UPLOAD_PATH` on its own shared folder (e.g.
`/volume1/immich`) instead of inside the stack directory. Snapshots, backup jobs and retention can then be set
separately from the container configuration, and the stack directory stays small.

- **Permissions:** grant the `PUID` user read/write on the shared folder explicitly. A new Synology shared
  folder only allows the `administrators` group; the container runs without that group and gets
  `EACCES` on the `.immich` marker files.
- **Service user (recommended):** create a dedicated user (e.g. `immich`, group `users`) with all
  applications denied and access to this folder only, and use its UID as `PUID`. A compromised container then
  cannot reach other shares, and your own account can be limited to read access. Existing files need the new
  owner: `docker run --rm -v <folder>:/data alpine chown -R <uid>:100 /data/<subdir>` (also `./model-cache`).
- The folder belongs to Immich: do not add, rename or move files in it by hand. A name such as `immich` rather
  than `photos` avoids mistaking it for a normal photo share.
- **Recycle bin:** not useful. The DSM recycle bin only catches deletions via SMB/AFP/NFS and File Station;
  Immich deletes inside the container directly and has its own trash (Administration → Settings → Trash).
- **Snapshots** (Btrfs) protect against accidental deletions and failed updates; they do not replace a backup
  to another device.
- Set a **storage label** per user (Administration → Users) and enable the **storage template** before the
  first large import, so originals end up in readable folders such as `library/<label>/<year>/`.

To move an existing upload folder, stop `immich-server` and `immich-machine-learning`, copy the content with
`cp -a <old>/. <new>/` (includes the hidden `.immich` marker files), set `IMMICH_UPLOAD_PATH` and recreate the
server. Database paths stay valid because the container path (`/data`) does not change.

On an **encrypted shared folder** (Synology, eCryptfs) file names are limited to about 143 bytes, and imports
and thumbnail generation are slower. Enable automatic mounting at boot (Key Manager → *Mount on startup*);
if the folder is not mounted, Docker cannot create the bind mount and `immich-server` does not start. Docker
does not retry this later, even with `restart: unless-stopped`: after mounting, run
`docker compose up -d immich-server`.

## Importing an Existing Photo Library

Existing photos (e.g. from Synology Photos) are added as an *external library*. Immich indexes them in place
and never modifies or deletes them — the mount is read-only.

1. Set `IMMICH_EXTERNAL_PATH` in `.env` (e.g. `/volume1/photo`) and run `./stacks deploy immich`.
2. Administration → External Libraries → create a library with the import path `/usr/src/app/external`.
3. Add exclusion patterns for system folders:

   ```text
   **/@eaDir/**
   **/#recycle/**
   **/#snapshot/**
   ```

   `@eaDir` contains thumbnails generated by Synology; without the pattern they are imported as photos.

4. Start a scan. The first run (thumbnails, faces, smart search) can take hours to days on a small CPU.

Albums, people and tags from other photo managers are not imported, only the files.

## Database

The Postgres image includes VectorChord and pgvector for smart search
(`ghcr.io/immich-app/postgres:<pg>-vectorchord<x>-pgvector<y>`). Immich supports Postgres 14 to 19.

- `DB_STORAGE_TYPE` tunes Postgres for `HDD` or `SSD`.
- A major Postgres upgrade requires a dump and restore, see
  [Backup and Restore](https://docs.immich.app/administration/backup-and-restore). Restore with the `sed`
  command from the documentation, otherwise the restore fails on the `search_path`.
- Since Postgres 18 the data is mounted at `/var/lib/postgresql` (versioned subdirectory), not
  `/var/lib/postgresql/data`.
